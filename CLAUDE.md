# Trade Management Systems

Scheduling + route planning app for solo service businesses (first user: a
lawn mowing round). Django 5 + django-ninja backend, Vite/React/TS frontend,
typed API client generated by kubb.

## Architecture in one minute

- **Same-origin everything**: the Vite dev server (and nginx in prod) proxies
  `/api`, `/_allauth`, `/accounts`, `/admin`, `/static`, `/media` to Django.
  Auth is plain session cookies + CSRF — no CORS, no tokens.
- **Auth** is django-allauth **headless** (`/_allauth/browser/v1/...`):
  email+password, Google (redirect flow), password reset, email verification.
  Frontend client: `frontend/src/lib/allauth.ts`.
- **API client is generated**: django-ninja exports OpenAPI → kubb generates
  axios clients + TanStack Query hooks into `frontend/src/gen/` (committed).
  The `operation_id` on each endpoint becomes the hook name
  (`listTrades` → `useListTrades`). Never edit `src/gen/` by hand.
- **Recurrence**: `AppointmentSeries` lazily materializes `Job` rows
  (see `backend/core/services/occurrences.py` — the correctness core).
- **Routing/geocoding**: Nominatim + OSRM (public OSM servers) with haversine
  fallback, in `backend/core/services/{geocode,routing}.py`.
- **Photos**: S3-compatible storage (MinIO in compose, django-storages).
- **Push notifications are mocked**: `core/services/notifications.send_push`
  writes to the `Notification` outbox; the future React Native app swaps in
  FCM/APNs there only.

## Commands (docker required; `just --list` for everything)

```sh
just dev        # full stack: Postgres + MinIO + Django + Vite (localhost:5173)
just codegen    # backend OpenAPI -> frontend/src/gen (run after ANY API change)
just test       # backend test suite
just lint       # ruff + tsc
just manage <…> # any manage.py command in the backend container
```

Without docker: `cd backend && uv run python manage.py …` (SQLite fallback)
and `cd frontend && npm run dev` work standalone.

## Hard rules

- **Every** ninja endpoint filters by `user=request.auth` (single-operator
  multi-tenancy). Add a cross-user isolation test for every new endpoint
  (pattern: `backend/core/tests/test_api.py`).
- After changing models/schemas/endpoints: `just codegen`, and fix frontend
  compile errors in the same change — CI builds the frontend against the
  committed `src/gen/`.
- Give every `TextChoices` class used in schemas a **globally unique class
  name** (e.g. `JobStatus`, not `Status`) — duplicate names silently clobber
  each other in the OpenAPI components.
- kubb types Decimal fields as `number | string`; forms send **strings**.
- Dates/times are naive local (`Pacific/Auckland`); never introduce UTC
  conversions into scheduling math.
- shadcn components are **vendored** in `frontend/src/components/ui/` — add
  new ones with `npx shadcn@latest add <name>` or by hand in the same style.
- Migrations: `just manage makemigrations` — CI fails if models and
  migrations drift.

## MCP servers (.mcp.json)

- `postgres` — query the local dev database (needs `just dev` running;
  connection: `postgresql://app:app@localhost:5432/app`).
- `playwright` — drive a real browser against http://localhost:5173 to
  verify UI changes end-to-end (login, click through the schedule, etc.).

## Releases

Push a branch named `release/X.Y.Z` → CI tags images `X.Y.Z`, creates git tag
`vX.Y.Z`, and publishes a GitHub Release. Every branch push already publishes
images tagged with the branch name + SHA to GHCR.
